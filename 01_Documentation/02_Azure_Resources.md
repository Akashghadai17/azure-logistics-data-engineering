# Azure Resources

## Overview

This document describes the Azure resources created for the **Logistics Azure Data Engineering Project**.

The resources provide the infrastructure required for:

* Data storage
* Data processing
* Metadata management
* ETL audit logging
* Secret management
* Pipeline orchestration

The project is deployed primarily in the **Central India** Azure region.

# 2. Azure Data Lake Storage Gen2

Azure Data Lake Storage Gen2 is used as the main data storage layer of the project.

It stores source data and processed data from different stages of the Medallion Architecture.

## Storage Account

The storage account follows a naming pattern such as:

```text
stlogisticsdev<unique-number>
```

Example:

```text
stlogisticsdev01
```

Because Azure Storage Account names must be globally unique, the exact deployed name can contain a different unique suffix.

---

## Hierarchical Namespace

**Hierarchical Namespace** is enabled on the storage account.

This provides ADLS Gen2 functionality and allows data to be organized using directory structures.

---

## Main Container

```text
logistics
```

The container is configured as a private container.

---

## Directory Structure

```text
logistics
│
├── landing
│   ├── sales
│   └── appointment
│
├── bronze
│
├── silver
│
├── gold
│
├── logs
│
└── archive
```

---

## Landing Layer

The `landing` directory stores incoming source files before they are processed.

```text
landing/
│
├── sales/
│
└── appointment/
```

### Sales

```text
landing/sales/
```

Stores incoming Sales CSV files.

### Appointment

```text
landing/appointment/
```

Stores incoming Appointment CSV files.

---

## Bronze Directory

```text
bronze/
```

Stores raw or near-raw data after initial ingestion and validation.

---

## Silver Directory

```text
silver/
```

Stores cleaned, transformed, and standardized data.

---

## Gold Directory

```text
gold/
```

Stores business-ready analytical data.

The final Gold data includes:

```text
DIM_APPOINTMENT_DATA
FACT_SALES
```

---

## Logs Directory

```text
logs/
```

Stores file-based or processing log information generated by the data pipeline where required.

---

## Archive Directory

```text
archive/
```

The Archive directory is used for files that have already been processed.

Instead of keeping successfully processed files in the Landing directory, files can be moved to Archive.

This helps separate:

```text
New Files
   ↓
Landing

Processed Files
   ↓
Archive
```

This makes it easier to identify which source files still need processing.

# 3. Azure SQL Database

Azure SQL Database is used to maintain **metadata configuration** and **ETL audit information** for the project.

## Database Name

```text
logisticsdb
```

---

## SQL Schemas

Two main schemas are used:

```text
metadata
audit
```

---

## Metadata Schema

The `metadata` schema stores configuration required by the ETL pipeline.

Important tables include:

```sql
metadata.OBJECTS_CONFIGURATION
```

and:

```sql
metadata.OBJECTS_COLUMN_MAPPING
```

---

## metadata.OBJECTS_CONFIGURATION

This table stores object-level ETL configuration.

It can contain information related to:

* Source object
* Target object
* Source path
* Target path
* Processing layer
* File configuration
* Incremental load configuration
* Active/inactive status

The ETL notebooks can read this information instead of hard-coding every configuration value.

---

## metadata.OBJECTS_COLUMN_MAPPING

This table stores source-to-target column mapping information.

It is used during transformations such as:

```text
Source Column
      ↓
Target Column
      ↓
Target Data Type
```

This allows the Silver transformation logic to apply mappings dynamically.

---

## Audit Schema

The `audit` schema stores information about ETL executions.

Main table:

```sql
audit.ETL_LOG
```

---

## audit.ETL_LOG

The ETL log table is used to record information such as:

* ETL process name
* Source object
* Target object
* Start time
* End time
* Record count
* Status
* Error message

Example statuses:

```text
STARTED
SUCCESS
FAILED
```

---

## Azure SQL Purpose

```text
Azure SQL Database
        │
        ├── metadata
        │     ├── OBJECTS_CONFIGURATION
        │     └── OBJECTS_COLUMN_MAPPING
        │
        └── audit
              └── ETL_LOG
```

Azure SQL is therefore not used as the main analytical storage layer.

Its main role in this project is:

* ETL configuration
* Metadata management
* ETL logging
* Pipeline monitoring

---

# 4. Azure Key Vault

Azure Key Vault is used to securely store sensitive information required by the ETL pipeline.

Sensitive credentials should not be hard-coded directly inside Databricks notebooks or source code.

---

## Stored Secrets

Important secrets include:

```text
sql-server-name
sql-database-name
sql-username
sql-password
```

These secrets are used when Databricks needs to connect securely to Azure SQL Database.

---

## Security Flow

```text
Azure Key Vault
      ↓
Store Secrets
      ↓
Databricks Secret Scope
      ↓
Databricks Notebook
      ↓
Azure SQL Connection
```

---

## Databricks Secret Scope

The Databricks secret scope used in the project is:

```text
project-scope
```

The notebook retrieves secrets securely instead of writing credentials directly into code.

Conceptually:

```python
dbutils.secrets.get(
    scope="project-scope",
    key="sql-username"
)
```

---

## Benefits

Azure Key Vault provides:

* Secure secret storage
* Centralized credential management
* Reduced hard-coded credentials
* Better security
* Easier credential updates

# 6. Azure Data Factory

Azure Data Factory is used as the **orchestration service** for the project.

ADF controls the execution of the Databricks processing workflow.

Its purpose is not mainly to transform the data itself.

Databricks performs the main transformations, while ADF controls the pipeline execution.

---

## ADF Responsibility

ADF is used for:

* Pipeline orchestration
* Databricks notebook execution
* Dependency management
* Activity sequencing
* Pipeline monitoring
* Failure handling

---

## Orchestration Flow

```text
Azure Data Factory
        ↓
Trigger Databricks Processing
        ↓
Bronze Processing
        ↓
Silver Processing
        ↓
Data Quality Checks
        ↓
Gold Processing
        ↓
Incremental Processing
        ↓
ETL Logging
```
